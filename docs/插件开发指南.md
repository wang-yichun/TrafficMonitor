# TrafficMonitor 插件开发与协作约定

这份文档供后续维护者和编码代理接手时使用。它记录本机当前实际运行方式、插件接口约定和已经确认的展示/数据语义。修改前先读这份文档及对应插件 README，再核对代码、脚本和当前用户指令；代码和正在运行的设置决定当前事实，文档中的例子用于解释约定。

## 当前仓库与运行位置

- 宿主源码：`D:\Projects\TrafficMonitor`
- 独立插件源码：`D:\Projects\TrafficMonitorPlugins\Plugins\<PluginName>`
- 当前运行宿主：`D:\Projects\TrafficMonitor\TrafficMonitor.exe`
- 当前插件目录：`D:\Projects\TrafficMonitor\plugins\`
- 当前 Codex 插件唯一源码：`D:\Projects\TrafficMonitorPlugins\Plugins\CodexUsage`。宿主仓库不再维护 CodexUsage 的源码副本。
- 插件仓库其他例子：`Plugins\iKuuuTraffic`、`Plugins\PluginTemplate`；宿主自带 `PluginDemo` 展示基础 API 和绘图方式。

当前已检查到运行中的进程路径为仓库根目录的 `TrafficMonitor.exe`。构建输出目录不等于运行目录：标准版宿主构建输出为 `D:\Projects\TrafficMonitor\Bin\x64\Release\TrafficMonitor.exe`，独立插件构建输出在插件仓库的 `bin\x64\Release\`。安装脚本再把它们部署到运行目录。`config-presets\preferred\README.md`、旧交接记录或其他旧笔记若提到 Bin 或 `D:\STools` 是运行位置，须以当前进程、脚本的目标路径和本文件的当期状态复核，不能据此直接改旧目录。

开始工作先分别查看两个仓库的 `git status --short --branch` 和相关 diff；保留用户已有改动，避免使用会丢弃改动的 reset、checkout、clean 操作。还须读取当时适用的 `AGENTS.md` 和用户提供的协作指令。

## 已确认的展示与数据验收条件

这些条目记录已确认的用户可见行为。后续需求明确改变其中某项时，以最新要求为准，并同步修改实现和本文件。下文标为“建议”的内容是通用工程做法，不代表额外产品限制。

- 任务栏保持紧凑并跟随深浅主题，避免重复标题行。iKuuu 的 quota/today 项目不再显示单独的首行 `iKuuu` 标题；保留紧凑左对齐布局。Codex 重置卡横向间距按用户确认的紧凑值排布，同时保持卡片尺寸和垂直布局。
- iKuuu 的灰色底轨先画，剩余账户额度按真实剩余比例填充；今日已用额度是紧邻主填充的低对比叠层。关闭宿主状态条时隐藏这层。底轨浅色为 RGB(194,202,211)，深色为 RGB(82,91,101)。
- 数据含义必须直观且可追溯。iKuuu Tunnel 适配器字节数不代表账号配额；UIA 当前未暴露数据时标记最后成功值为旧数据，首次读取成功前显示不可用，不编造配额或今日用量。
- Codex 的 5 小时/7 天配额显示保留各自额度、重置时间和时间比例；卡片与进度布局保持用户已确认的紧凑排版。会话 Token 日统计按事件日期增量口径，详细账号/Token 内容显示在插件详情弹窗，普通宿主 tooltip 只显示短摘要。

通用建议：新展示项的 ID 保持稳定；用户修改配置时优先保留当前 `config.ini` 状态；视觉改动要在真实宿主任务栏确认。它们用于减少回归，不应覆盖后续明确要求。

## 变更归属与优先级

- 插件的数据抓取、数据解释、展示项、选项和插件自绘，改独立插件仓库对应项目。
- 插件接口、宿主任务栏状态条、宿主窗口行为或宿主安装/生命周期，改宿主仓库。
- 改了 `include\PluginInterface.h`、宿主调用约定或宿主绘制行为时，要同步考虑独立插件和 PluginTester；插件的唯一业务实现仍保留在插件仓库。
- 若只改 DLL 业务逻辑，不在宿主仓库重新造一个插件源码副本。宿主 API 或状态条绘制改动时，宿主和依赖该行为的插件应使用匹配架构、匹配版本构建并部署。
- 用户最新明确的要求优先于旧文档、历史截图、默认配置和代理建议。涉及颜色、字号、间距、文字、状态含义时，保留用户确认的可见行为；新要求有冲突时按最新要求改，并更新对应记录。

## 接口与生命周期

接口定义以宿主 `include\PluginInterface.h` 为准；插件仓库也带有 `include\PluginInterface.h`，两边须保持一致。当前接口版本为 API 9。插件不得自行改写 `ITMPlugin::GetAPIVersion()` 的版本号，也不能假设新 API 在旧宿主存在；调用宿主接口前按 `ITrafficMonitor::GetAPIVersion()` 能力检查。

宿主用 `LoadLibrary` 加载 `plugins\*.dll`，查找导出符号 `TMPluginGetInstance`，再枚举 `GetItem(0...)`，直到返回空指针。插件应导出 C 链接工厂，并返回长期存活的单例或静态对象。每个可展示项目的 `GetItemId()` 必须稳定且唯一；配置会保存这些 ID，改 ID 会使用户原来的显示选择失效。

宿主周期性调用 `DataRequired()`，随后传入 `OnMonitorInfo()`。`GetItemValueText()`、绘图、宽度测量和 `GetTooltipInfo()` 可能在界面刷新或鼠标提示过程中频繁调用。数据抓取、磁盘扫描、网络请求和等待操作放在刷新逻辑或自有 worker 中；绘图与文本 getter 读取已准备好的快照，不做慢 I/O。宿主源码当前在监控更新流程中调用 `DataRequired()`，但插件不要依赖未写入接口约定的线程亲和性。跨线程数据使用锁或原子量保护，并让绘图所需的快照和返回文本在调用期间有效。

需要后台线程的插件使用 API 9 的 `OnShutdown()` 停止、唤醒并 join worker；宿主 `PluginManager` 在卸载 DLL 前，对 API 版本大于等于 9 的插件调用它。不要让线程或回调在 `FreeLibrary` 后继续执行插件代码。配置目录通过 `EI_CONFIG_DIR`/`GetPluginConfigDir()` 获取，不要硬编码某台机器的用户目录。

`GetTooltipInfo()` 作为宿主普通鼠标提示的来源，宿主可能在任务栏显示项为空时也调用它。因此返回短小、稳定的状态摘要；交互详情应放插件自己的详情窗口或弹层。不要将完整 JSON、长多行报告或变化频繁的大对象放进普通 tooltip。Codex 插件的完整账号与 Token 明细保留在其详情弹窗中，宿主 tooltip 仅显示简要额度状态。

## 最小接口骨架

以下例子说明必需结构；项目还需配置预编译头、资源、导出和正确的 x64 DLL 工程设置。可直接从 `D:\Projects\TrafficMonitorPlugins\Plugins\PluginTemplate` 或宿主 `PluginDemo` 起步。

```cpp
#include "PluginInterface.h"
#include <string>

class SampleItem final : public IPluginItem {
public:
    const wchar_t* GetItemName() const override { return L"示例"; }
    const wchar_t* GetItemId() const override { return L"SampleItem1"; }
    const wchar_t* GetItemLableText() const override { return L"示例"; }
    const wchar_t* GetItemValueText() const override { return m_value.c_str(); }
    const wchar_t* GetItemValueSampleText() const override { return L"999"; }
private:
    friend class SamplePlugin;
    std::wstring m_value{L"--"};
};

class SamplePlugin final : public ITMPlugin {
public:
    IPluginItem* GetItem(int index) override {
        return index == 0 ? &m_item : nullptr;
    }
    void DataRequired() override { m_item.m_value = L"42"; }
    const wchar_t* GetInfo(PluginInfoIndex index) override {
        return index == TMI_NAME ? L"示例插件" : L"";
    }
private:
    SampleItem m_item;
};

extern "C" __declspec(dllexport)
ITMPlugin* TMPluginGetInstance() {
    static SamplePlugin plugin;
    return &plugin;
}
```

实际工程中，接口 getter 的字符串应由插件持有，不能返回临时局部变量的 `c_str()`。若从后台线程更新值，用快照和互斥锁保护读写；避免返回一个马上会被另一个线程重写或释放的缓冲区。

## 任务栏绘制与紧凑主题适配

普通文本项返回标签、当前值和示例值，由宿主排版。自绘项需 `IsCustomDraw() == true` 并实现 `DrawItem()`；宽度可用 `GetItemWidth()` 返回 96 DPI 下逻辑宽度，或优先实现 `GetItemWidthEx(HDC)` 根据当前绘图上下文测量实际宽度。自绘区域最小宽度可能小于宿主实际传入的 `w`。参考 `PluginDemo\CustomDrawItem.cpp` 和 Codex/iKuuu 自绘项目。

绘图回调提供 `dark_mode`，自绘颜色需考虑深浅背景，避免写死只适合一种主题的颜色。若通过 `IPluginDrawer` 的 `DrawItemEx()` 绘制，接口色彩参数为 `0xBBGGRR`；绘图能力版本、DPI 和宿主设置须按接口传入值处理。任务栏项目应优先保持紧凑：短标签、足够文字间距、避免重复标题行；调整卡片或列间距时，让绘制和宽度测量共用同一套尺寸计算，防止文本与实际布局错位。

资源状态条由 `IsDrawResourceUsageGraph()` 和 `GetResourceUsageGraphValue()` 提供，比例值范围为 `0.0–1.0`。默认 0 不显示，1 跟随宿主资源图设置，2 始终用从左到右的水平条。当前宿主仍要求 `show_status_bar` 开启；类型 2 忽略历史曲线类型选择，宿主先画背景轨道，再按比率从左向右填充，颜色来自 TrafficMonitor 状态条主题/手动颜色设置。API 6 以上宿主会通过 `EI_DRAW_RESOURCE_USAGE_GRAPH` 告诉插件当前是否具备绘制上下文。

对额度类数据，明确比率方向：`GetResourceUsageGraphValue()` 是“填充比例”，不是字段名称的隐含猜测。iKuuu 剩余额度条用剩余占比，Codex 的 5 小时/7 天时间条表示剩余时间占比。若还要叠加“今日已用”之类的第二种含义，应在宿主状态条填充之后由插件按当前图表上下文叠加，并限制在有效范围内；关闭状态条时不绘制叠加层。iKuuu 当前确认的底轨浅色 RGB(194,202,211)、深色 RGB(82,91,101)，今日用量叠层在两种主题下使用低对比灰色。不要再绘制重复的第二条主进度条。

## 数据语义、隐私与用户可见行为

- 数字应保留源数据真实含义。iKuuu Tunnel 网卡计数器可用于速度或会话字节统计，不能冒充 iKuuu 账户配额。当前 iKuuu 配额/今日用量依赖 UI Automation 中应用实际暴露的文本；页面不含统计时保留最后成功值并标记旧数据，首次成功读取前显示不可用。不得为了填满显示项而推算不存在的账户额度。
- iKuuu 插件只读取窗口可访问文本，不导航、不点击、不发送键盘输入、不读取凭据、不主动请求网络。UIA 树无统计意味着源应用未暴露所需值，先确认数据来源，不应只放宽数字正则。
- Codex Usage 仅展示 Codex 数据。凭据只从 Codex 当前用户配置读取并通过 HTTPS 请求官方使用量/重置额度接口；会话 Token 统计来自本地 JSONL 事件。按事件时间和累计计数增量处理，跨日和活动/归档副本需要去重，不能把今天以前累积量全部算进今天。完整细节留在插件弹窗，普通 tooltip 保持短摘要。
- Codex 5 小时和 7 天额度各自具有独立重置时间和时间进度。工作日、调休与节假日标记按插件 `calendar\YYYY.txt` 数据解释，北京日期为准；无年份文件时按周一至周五回退，不要把前一年度假期表继承到新年。
- 任务栏是狭窄、主题相关的显示面。保持信息一眼可读和用户已确认的间距、标签、明暗对比；改动一项的含义、单位或过期表现时，连同 tooltip、详情弹窗和宽度测量一并检查。
- 先读取当前 `config.ini` 与 `global_cfg.ini`，尊重用户当前启用/禁用和显示项选择。首选配置仅在用户明确要套用时使用；一般插件更新只替换 DLL，并保留现有配置。安装器可能备份并修改配置，执行前理解参数行为。

## 构建、安装与核验

### 构建和安装

在两仓库相邻的当前布局中，`InstallFromRepos.ps1` 是宿主+Codex 的构建安装入口：默认 x64 Standard，构建宿主到 `Bin\x64\Release`，构建 `TrafficMonitorPlugins\Plugins\CodexUsage\CodexUsage.vcxproj` 到插件仓库 `bin\x64\Release\CodexUsage.dll`，然后把宿主安装到本仓库根目录、DLL 放入 `plugins`，并校验安装 DLL 与构建 DLL 的 SHA256。默认升级保留已有配置；新安装才自动应用首选配置，`-ApplyPreferredSettings` 会显式套用首选配置。`-ValidateOnly` 只解析路径和检查先决文件，不构建、不复制、不停止/启动进程。

```powershell
# 只检查路径和输入是否齐全
.\InstallFromRepos.ps1 -ValidateOnly

# 构建并部署宿主与 Codex 插件到当前仓库根目录
.\InstallFromRepos.ps1
```

`RestartTrafficMonitor.ps1` 的目标是其脚本所在目录下的 `TrafficMonitor.exe`。它关闭并重启该宿主，若相邻插件仓库有更新构建产物，只安装 Codex DLL 和缺失的日历文件。它不会将 Bin 中的新宿主 exe 复制到根目录，也不构建宿主。因此，仅在宿主源码不需更新时用它部署新插件；改宿主源码/API/任务栏绘制后，先用 `InstallFromRepos.ps1` 部署新宿主，再正常启动。`ApplyPreferredSettings.cmd` 调用重启脚本的 `-UseRepositorySettings`，会覆盖当前配置为仓库首选快照，应仅在明确需要恢复该配置时运行。

iKuuu 的独立安装器为 `TrafficMonitorPlugins\Plugins\iKuuuTraffic\Install-iKuuuTraffic.ps1`，默认指向当前宿主根目录。它备份配置和旧 DLL、启用固定显示 ID、复制 DLL、校验 SHA256 并可重启宿主。运行安装动作前先用 `-ValidateOnly` 检查目标路径和新配置；确认默认或显式 `-HostDirectory` 指向预期运行目录。

### 每次交付必做的核验

1. 在宿主与插件仓库分别确认分支和工作区状态；只提交/安装本次意图涉及的改动，不覆盖用户已有的未提交工作。
2. 对插件构建确认架构与宿主一致（当前为 x64、Release），并核对导出符号 `TMPluginGetInstance`。若宿主改动影响 API 或绘图，再构建、部署宿主和相关插件。
3. 比对构建 DLL 与运行目录 `plugins\<Plugin>.dll` 的 SHA256。对宿主更新，核对 `Bin\x64\Release\TrafficMonitor.exe` 与根目录运行 exe 的版本/哈希或安装输出，不能把“编译成功”当作“运行已更新”。
4. 确认进程可执行路径指向 `D:\Projects\TrafficMonitor\TrafficMonitor.exe`；必要时读进程已加载模块，确认插件 DLL 来自 `D:\Projects\TrafficMonitor\plugins\`。查看配置中插件是否被禁用、项目 ID 是否在 `plugin_display_item` 中。
5. 测试器适合检查 DLL 装载、基础事件和绘制预览；它不能替代宿主集成核验。对于任务栏外观或真实点击行为，需在当前宿主、当前配置、真实任务栏中检查。代码检查或像素回归不能表述成已完成人眼视觉验收。
6. 报告验证边界：明确区分构建成功、安装 DLL 哈希匹配、宿主加载确认、任务栏/鼠标实际验收。没有做的检查写清楚。
